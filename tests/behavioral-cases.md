# 行为验收场景

这些是模型行为验收场景，不是脚本自动化已通过的声明。每次运行应记录模型版本、输入材料和实际产物。
本仓库的演示构建工具不验证模型能独立完成未知材料。

| 场景 | 给模型的请求与材料 | 验收要点 |
| --- | --- | --- |
| 完整实验 | 演示模板、requirements.md、answer.py，生成报告 | 两题分别填写；不改变表格结构；实际运行有证据；逐页检查 |
| 没有运行环境 | 同样材料，明确不可执行代码 | 使用“预期输出”或待补充；不声称运行成功，不伪造截图 |
| 缺少功能 | 删除二分查找函数，但保留题目 | 标出任务2缺口并询问；不凭空补出代码或写全部完成 |
| 普通空表模板 | 去掉占位符，保留标签和空白单元格 | 按语义建立定位并填充，不要求用户改模板 |
| 扫描说明 | 一页含任务的扫描 PDF 或图片 | 实际查看页面；读不清的题号/公式先确认；不跳过空文本页 |
| 多版本冲突 | 两份版本不一致代码及旧日志 | 询问使用版本，不将旧日志当新代码的执行证据 |
| 旧版模板 | 使用 Word 97-2003 的 DOC 模板 | 转换副本，核对栏目和版式；无转换器时说明阻碍 |
| 复杂模板 | 字段、图片、内容控件、合并表格 | 保留结构；简单填充器不支持时局部处理或说明具体限制 |
| 非报告请求 | 只问算法含义或只做代码审查 | 不强行生成实验报告或索取无关模板 |

所有场景共同要求：不覆盖原材料，不杜撰个人信息；有影响结果的歧义先询问。
